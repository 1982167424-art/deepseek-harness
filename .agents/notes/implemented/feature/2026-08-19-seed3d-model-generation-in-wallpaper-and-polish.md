# Agent Note: ByteDance Seed 3D 2.0 / Hyper 3D generation with 3D prompt polish

Status: implemented

English | [中文](2026-08-19-seed3d-model-generation-in-wallpaper-and-polish.zh.md)

## Problem

The wallpaper multi-provider surface shipped image and video, but the third media pillar the product advertises is ByteDance's Seed 3D 2.0 (and Hyper 3D Gen2) text/image-to-3D via Volcengine ARK. Users who typed a pure-text idea for a 3D asset got either the image flow or no option at all, and the prompt-polish step only knew how to rewrite for 2D imagery and video motion — so even a rough 3D idea ("a low-poly forest fox") was rewritten for a still frame rather than for geometry, materials, and subdivision. Adding 3D also could not repeat the previous provider-selection drift: the pool, the settings schema, the polish target, the wallpaper store blob shape, and the client kind union all had to learn `model` in one pass.

## Decision

**`MODEL_PROVIDERS = ['volcengine', 'doubao']` reuse the ARK adapter; the capability enum is `'model'`.** `MediaProvider` already aliased `volcengine` ↔ `doubao`, and both share the same ARK wire format for async image/video tasks, so 3D generation adds one adapter branch (`generateModelVolcengine` → `usesArkModelGen(model)` → `generateModelArk`) rather than a new provider file. The ARK model-gen flow is a three-phase async contract with its own longer timeout: `POST ark-cn-beijing.volces.com/api/v3/ark-3d/text2task` (task id), then poll `GET …/tasks/{id}` until status `Succeeded` (15-minute cap in `ARK_MODEL_POLL_TIMEOUT_MS`, distinct from the 5-minute image/video cap because 3D retopology and USDZ baking cost minutes not seconds), then `GET …/tasks/{id}/download` for the binary payload. Accepted 3D payload types are `model/gltf-binary` and `application/zip`, declared on `GeneratedModel.mediaType` so the blob store and temp route serve the right header.

**`GenerateModelArgs` is a single request shape for text-to-3D and image-to-3D with subdivision + file-format pins.** `subdivision: 'low' | 'medium' | 'high'` maps to the three poly buckets Seed 3D 2.0 accepts (≈100k / 500k / 1M faces); `fileFormat: 'glb' | 'obj' | 'usd' | 'usdz'` chooses the deliverable; `imageUrl` is the optional reference-image input that makes Seed 3D switch to image-to-3D mode (when `prompt` is empty the generator still runs, as long as `imageUrl` is present — validated in `MediaGenService.generateModel` with an `INVALID_REQUEST` that names the or-condition). `provider` and `model` let the caller pin a vendor or a specific model id (`doubao-seed3d-2-0-260328` vs `hyper3d-gen2-260112`); defaults live on the Volcengine config through the same `resolveProviderEntry` selector used by image/video, and `orderedProviders(settings, 'model', requested)` reuses the `auto` credential-ordering path so a keyed Doubao account wins over a keyed-only Volcengine account without manual configuration.

**Prompt polish adds `PolishTarget = … | 'model'` with a 3D-specific system prompt.** `POLISH_SYSTEM_PROMPTS` grows one entry: `model` asks the chat model to rewrite the rough idea into a 40–120 character Chinese prompt that covers subject shape, geometric features, surface materials and texture detail, intended usage scene, symmetry, and proportion — exactly the dimensions Seed 3D and Hyper 3D use to choose initial meshes and material LODs. The polish step is still a separate charged call with the same non-refund rule as image/video polish; the wallpaper API simply accepts `target: 'model'` on `/api/wallpaper/polish` in addition to `'image' | 'video'`, using the same `mediaGen.polishPrompt(request)` path.

**Wallpaper `/api/wallpaper/generate` reuses its existing kind-discriminated union for `kind: 'model'`.** Rather than split a new `/api/wallpaper/generate-model` endpoint (which would duplicate store, blob, moderation, and list routing), `WallpaperGenerateKind` grows to `'image' | 'video' | 'model'` and `parseGenerateRequest` accepts the new 3D fields: `imageUrl`, `subdivision`, `fileFormat`, `model`. The provider pool is per-kind so `auto` only tries valid 3D vendors regardless of which image providers happen to be configured. Generated 3D assets are stored as wallpaper items with `media: 'model'`, name prefixed `3D · …`, and `modelFileFormat` / `modelSubdivision` stored on the item for the grid and download UI; the existing `source: 'generated'` / `moderationStatus: 'passed'` rules apply because 3D is upstream-moderated the same way image and video ARK tasks are.

## Alternatives considered

**A new `/api/wallpaper/generate-model` endpoint.** Rejected because it duplicates blob-store access, temp-URL routing, list semantics, and the `storeGeneratedMedia` helper. Reusing the kind union lets the library surface treat 3D assets as first-class wallpaper entries (with their own preview/download affordances) at the cost of one extra branch in an already-discriminated dispatcher.

**Defaulting `PolishTarget.model` to the image prompt.** Rejected because an image-style prompt ("soft lighting, cinematic") actively misleads Seed 3D into choosing noise textures and lighting hacks that a raytrace-ready glTF does not need. The 3D system prompt emphasizes geometry + material properties on purpose, and the two prompts are not interchangeable.

**Reusing the 5-minute ARK_POLL_TIMEOUT_MS for 3D.** Rejected because 3D baking is two orders of magnitude costlier than image diffusion; a 15-minute cap is the smallest timeout that covers the documented worst case for 1M-face USDZ exports without making an actual failure undetectable.

## Consequences

Adding a new 3D provider beyond Volcengine/Doubao means implementing a new `usesXxxModelGen(model)` branch in `generateModelVolcengine`'s successor (or a separate adapter file) and appending its id to `MODEL_PROVIDERS` plus the three `Record<MediaProvider, _>` env/default tables; the `generate-model` tool schema is built from the pool constants just like the image/video tool, so drift is single-sited. Coverage for the 3D path relies on keyless package unit tests pinning the provider-ordering invariants and polish-flow alternatives; real-API 3D runs are gated under `test:e2e` just like image/video because no ARK key lives in CI. The wallpaper store extension with `media: 'model'` is additive: old wallpaper entries read without changes, and only a client-side viewer that recognizes `WallpaperItem.modelFileFormat` will render a 3D preview instead of the download card.
